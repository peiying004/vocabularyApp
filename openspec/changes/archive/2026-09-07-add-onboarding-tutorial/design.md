## Context

VocTest 是一個 SwiftUI + SwiftData 的 iOS App，根 view 是 `VocTest/ContentView.swift`，它提供全域唯一的 `NavigationStack` 並以 `VocTest/Views/HomeView.swift` 作為起點。`VocTest/VocTestApp.swift` 只負責建立 window 與註冊 modelContainer。

目前的現狀限制了做法：

- 全專案**沒有任何** `@AppStorage` 或 `UserDefaults` 使用，本次是第一次引入使用者偏好的持久化。
- `Assets.xcassets` 只有 `AppIcon`，專案沒有任何圖片資產，`docs/screenshots/` 目錄也不存在。
- 首次啟動時 SwiftData 資料庫是空的，`DeckListView` 與 `GrammarDeckListView` 都是空清單。
- `HomeView` 目前沒有 toolbar，只設定 `.navigationTitle("VocTest")`。

## Goals / Non-Goals

**Goals:**

- 讓初次開啟 App 的使用者在四頁之內理解「貼上 Markdown → 自動切批 → 四選一測驗 → 答錯重練」這條核心流程。
- 教學可提早關閉，且關閉後不再自動騷擾。
- 教學可隨時重看，不需要重裝 App。
- 保留日後演進成 coach mark 的結構，不需要重寫容器。

**Non-Goals:**

- 不做 coach mark（在真實 UI 元件上打光圈或指箭頭）。首次啟動時資料庫是空的，清單畫面沒有任何批次或題目可供標示；要讓 coach mark 有意義得先塞示範資料或攔截使用者的實際匯入操作，兩者都是比本次大一個量級的工程。
- 不做多語系。教學文案與 App 其餘畫面一致使用繁體中文硬編碼字串。
- 不新增示範資料（demo deck）。
- 不改動任何 SwiftData model、Parser、或 ReviewEngine 的既有行為。
- 不引入第三方套件。

## Decisions

### 以 overlay 掛在 ContentView，而非 fullScreenCover 或 sheet

教學遮罩以 `.overlay` 疊在 `ContentView` 的 `NavigationStack` 之上。

替代方案與否決理由：

- `.sheet`：可被使用者下滑關閉，且下滑不會經過我們的關閉流程，旗標寫入時機會分岔；視覺上也是從底部推起的獨立面板，看不到底下的首頁。
- `.fullScreenCover`：完全遮蔽首頁，教學期間使用者失去「我在哪」的脈絡；且它是不透明的，無法達成「隱約看得到首頁」的效果，也不具備日後改 coach mark 的結構。
- 掛在 `HomeView` 內部：`HomeView` 位於 `NavigationStack` 之內，一旦使用者導航到 DeckList，遮罩的生命週期會與導航狀態糾纏。掛在 stack 之外的 `ContentView` 沒有這個問題。

遮罩本身需攔截點擊（不可穿透到底下的首頁），教學顯示期間首頁不可操作。

### 以 AppStorage 旗標判斷首次啟動，而非以資料庫是否為空判斷

使用 `@AppStorage("hasSeenOnboarding")` 的布林值，預設 false。

否決「資料庫沒有任何 Deck 就視為首次」的理由：README 明列「編輯模式多選刪除」是常態功能，使用者把內容全部刪光是可預期的操作，那時教學會再次跳出來，行為不正確。

### 兩條結束出口寫同一個旗標

關閉按鈕（叉叉）與最後一頁的「開始使用」按鈕，兩者都把旗標設為已看過。使用者從任何一頁提早關閉，下次啟動都不再自動顯示教學。

否決「提早關閉不算看過」的理由：既然首頁有常駐的重看入口，反覆自動彈出只會造成困擾，而且沒有補償價值。

### 以 SwiftUI 繪製向量示意圖，而非使用螢幕截圖

四張示意圖全部用 SwiftUI 基本形狀與文字（例如 `RoundedRectangle`、`Text`、`Image(systemName:)`）疊出。

替代方案與否決理由：

- 真實螢幕截圖：卡片是浮在首頁上的小尺寸容器，整張手機截圖縮進卡片後文字不可讀；且需要維護淺色與深色兩套資產、以及 2x/3x 尺寸，而專案目前完全沒有圖片資產管線。
- 只放 SF Symbol 圖示：資訊量不足，無法表達「表格變成一疊卡片」這類轉換關係。

SwiftUI 繪製的圖是向量的，深色模式透過語意色彩自動跟隨，不需要維護第二套資產。

### 每頁都放主按鈕以固定卡片高度

卡片底部固定一顆主按鈕，前三頁為「下一步」、第 4 頁為「開始使用」。

否決的兩個替代方案：

- 主按鈕只在第 4 頁出現：翻到最後一頁時卡片變高、整張往上跳，滑動過程有明顯位移。
- 主按鈕只在第 4 頁出現、但前三頁留等高的隱形佔位：高度穩定了，但前三頁底部空出一大塊白，看起來像沒做完。

改成每頁都有主按鈕，空間有了意義，同時多給一條點擊前進的路徑 —— 對第一次開 App、還沒意識到卡片可以滑動的人來說，這比要求他自己發現滑動手勢更可靠，而這正是教學要解決的問題。

### 重看入口放在 Home shell 的 toolbar

`HomeView` 的 toolbar 右上角新增一個問號按鈕。經由此入口開啟教學時，不改動旗標。

否決「教學只顯示一次、無重看入口」的理由：使用者忘記內容後無法找回；且開發與測試期間每次都必須重裝 App 才能再看到教學。

## Implementation Contract

**Behavior:**

- App 啟動且已看過旗標為 false 時，首頁載入後自動浮出教學遮罩，停在第 1 頁。
- 遮罩為半透明，底下的首頁隱約可見但不可點擊。
- 遮罩中央是一張卡片，可左右滑動在 4 頁之間切換，卡片底部有頁面指示器顯示目前頁次。
- 每一頁由三部分組成：上方一張示意圖、中間一個標題、下方約四行說明文字。
- 卡片右上角有關閉按鈕，四頁皆可用。
- 卡片底部固定位置有一顆主按鈕：前三頁是「下一步」（前進一頁），第 4 頁是「開始使用」（結束教學）。按鈕位置與高度在四頁之間不變，翻頁時卡片不會忽高忽低。
- 按下關閉按鈕或第 4 頁的「開始使用」，遮罩消失、旗標設為已看過。
- 旗標為 true 時啟動，不顯示遮罩。
- 首頁 toolbar 的說明按鈕會開啟同一份教學遮罩，一律從第 1 頁開始；此路徑結束時旗標維持不變。

**四頁內容（標題與示意圖主題）:**

| 頁次 | 標題         | 說明重點                                             | 示意圖主題                       |
| ---- | ------------ | ---------------------------------------------------- | -------------------------------- |
| 1    | 兩條學習路線 | 單字看英文選中文；文法填空選答案                     | 兩張並列的路線卡片               |
| 2    | 貼上就能出題 | Markdown 表格自動解析，依 40 題一批自動切好          | 表格轉換成一疊批次卡片           |
| 3    | 四選一測驗   | 干擾選項從同批隨機抽取，不會在錯的幾張之間亂猜       | 一題四個選項，其中一個標為正解   |
| 4    | 答錯會再問一次 | 錯題重新插回佇列後方，全部答對才結束；結束後可只練錯題 | 佇列中的錯題繞回隊尾的循環箭頭   |

每頁的說明文字長度以四行為目標，不描述逐步操作細節。

**Interface / data shape:**

- 持久化鍵名：`hasSeenOnboarding`，型別為 `Bool`，預設 `false`，存於 `UserDefaults`（透過 `@AppStorage` 存取）。
- 頁面內容以一個具備 `Identifiable` 的頁面結構陣列表達，每個元素持有標題、說明文字、以及對應示意圖的識別方式；陣列長度為 4，且為靜態常數，不由使用者資料推導。

**Failure modes:**

- 旗標讀取不會失敗；鍵不存在時 `@AppStorage` 回傳預設值 `false`，等同首次啟動，這是刻意的行為。
- 教學不依賴任何 SwiftData 查詢，資料庫為空或載入失敗都不影響教學顯示。

**Acceptance criteria:**

- 手動驗證：四頁的卡片頂緣位置一致，以「下一步」從第 1 頁按到第 4 頁，卡片不發生上下位移。
- `VocTestTests/OnboardingTests.swift` 中的測試需驗證：頁面陣列恰有 4 個元素；每個元素的標題與說明文字皆非空字串；頁面標題依序為「兩條學習路線」「貼上就能出題」「四選一測驗」「答錯會再問一次」。
- 手動驗證：模擬器刪除 App 後重裝，首次開啟自動出現教學；滑到第 4 頁按結束，重開 App 不再出現；重新安裝後在第 2 頁按叉叉，重開 App 同樣不再出現；按首頁問號可再次開啟並停在第 1 頁。
- 手動驗證：教學顯示期間點擊底下首頁的「單字」按鈕位置，不會發生導航。
- 手動驗證：淺色與深色模式下，卡片、示意圖與文字皆清晰可讀。
- 既有測試全數維持通過。

**Scope boundaries:**

- 在範圍內：教學遮罩容器、4 頁內容與示意圖、旗標持久化、`ContentView` 掛載、`HomeView` toolbar 說明按鈕、上述單元測試。
- 不在範圍內：coach mark 的 anchor 定位機制、示範資料、多語系、`docs/` 底下任何文件的更新、`DeckListView` 與 `ImportView` 等任何測驗流程畫面的改動。

## Risks / Trade-offs

- [教學文案描述的流程與 App 實際行為脫節（例如日後批次大小從 40 改成別的數字）] → 說明文字集中在單一內容定義檔，且第 2 頁的批次大小敘述在該處以註解標示其來源，改動時只需修一處。
- [SwiftUI 繪製的示意圖在小螢幕（如 iPhone SE）上被壓縮或溢出] → 示意圖使用相對尺寸與 `layoutPriority`，並在實作後於最小支援機型上目視確認；卡片說明文字區允許在極小螢幕捲動。
- [遮罩攔截點擊的實作若寫錯，會出現「教學關不掉但首頁也點不到」的死鎖] → 關閉按鈕與結束按鈕的點擊區必須位於遮罩之上而非之下，驗收時明確測試提早關閉路徑。
- [首次引入 `UserDefaults` 旗標，測試若直接讀寫共用的 standard defaults 會污染其他測試] → 單元測試只驗證靜態頁面內容，不驗證 `@AppStorage` 讀寫；旗標行為以手動驗證涵蓋。
